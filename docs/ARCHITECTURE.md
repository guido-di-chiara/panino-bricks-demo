# Architecture — Panino Bricks Lab

This document explains how the lab fits together: the multi-agent topology, the
data model, the Lakebase memory layer, and the demo questions.

---

## 1. The big picture

Panino Bricks is a fictional Italian panino (sandwich) chain. The lab is a
**multi-agent assistant** for its staff, exposed through a Streamlit Databricks
App. A single **Multi-Agent Supervisor** ("Panino Bricks HQ") sits in front of two
specialist subagents and decides who answers each question.

```
                          ┌─────────────────────────────┐
   user (staff member) ──▶│  Streamlit App (Databricks)  │
                          │  - chat UI + store selector  │
                          │  - chat history in Lakebase  │
                          └──────────────┬──────────────┘
                                         │ invocations (streaming)
                                         ▼
                       ┌──────────────────────────────────┐
                       │  Multi-Agent Supervisor (MAS)      │
                       │  serving endpoint mas-<hash>       │
                       │  routes + synthesizes (Italian)    │
                       └───────┬───────────────────┬───────┘
                               │                   │
              structured data  │                   │  unstructured / procedural
                               ▼                   ▼
                  ┌─────────────────────┐  ┌──────────────────────────┐
                  │ Genie Space          │  │ Knowledge Assistant (KA) │
                  │ "Analista Vendite"   │  │ "Ops Bot"                │
                  │ NL -> SQL over 13    │  │ RAG over 6 internal PDFs │
                  │ Delta tables         │  │ on a UC Volume           │
                  └─────────┬───────────┘  └────────────┬─────────────┘
                            ▼                            ▼
                  Unity Catalog Delta tables    UC Volume (ka_documents/*.pdf)
```

**Why a supervisor?** Real questions mix structured and unstructured needs ("which
stores are low on mozzarella, and what's the reorder lead time?"). The supervisor
calls both subagents when needed and merges the answers, instead of forcing the
user to pick a tool.

**Auth model — runs as the caller.** The supervisor executes its tools using the
**caller's identity** = the app's service principal. That is why provisioning
grants the app SP `CAN_QUERY` on the MAS and KA endpoints, `CAN_RUN` on the Genie
space, `CAN_USE` on the warehouse, and UC `USE CATALOG / USE SCHEMA / SELECT`. A
human's permissions are not enough.

## 2. Lakebase as chat memory

The app persists conversations and messages in a **Lakebase** (managed Postgres)
instance, in schema `panino_app` (tables `conversations`, `messages`). This shows
Lakebase as a low-latency operational store alongside the analytical lakehouse.

- The app authenticates to Postgres with a **Databricks OAuth token** generated via
  the SDK (`generate_database_credential`), refreshed automatically (~50-min margin).
- The app SP must have a **Lakebase OAuth role** created with the `databricks_auth`
  extension (`databricks_create_role(..., 'SERVICE_PRINCIPAL')`) plus
  `GRANT CREATE, CONNECT, TEMPORARY`. A plain `CREATE ROLE` does **not** work for
  OAuth — this is the single most common setup failure.

## 3. The data model (13 Delta tables)

Generated by `src/01_generate_data.py`. ~200K orders over a 3-month window
(1 Apr – 30 Jun 2026) with realistic weekend, seasonal, holiday, new-store-opening,
and promo patterns. IDs are stable (`STR-*`, `PRD-*`, `SUP-*`, `ING-*`, `PRM-*`).

| Table | Grain | Notes |
|---|---|---|
| `stores` | one row per store | 37 paninoteche across Italian cities/regions; `opened_date` drives volume tiers |
| `products` | one row per panino | 29 panini: Classici, Gourmet, Vegetariani, Regionali, Stagionali, Premium, Senza Glutine |
| `toppings` | one row per extra | 12 extras (Doppia Mozzarella dominates) |
| `ingredients` | one row per ingredient | `reorder_threshold` for low-stock logic; `supplier_id` |
| `suppliers` | one row per supplier | `lead_time_days`, `reliability_score` |
| `promotions` | one row per promo | 15 promo types (BOGO, happy hour, loyalty, seasonal, …) |
| `customers` | one row per customer | 15K customers; `loyalty_tier` Bronze/Silver/Gold/Platinum |
| `orders` | one row per order/receipt | `order_total` (incl. discount), `tax` (10% IVA), `channel` In-Store/Mobile App/Online |
| `order_items` | one row per panino in an order | `size` (Junior/Classico/Maxi), `bread_type`, `toasting`, `sauce` |
| `order_item_toppings` | one row per topping on an item | extras per panino |
| `purchase_orders` | one row per supplier PO | 2K POs with expected vs actual delivery |
| `inventory_transactions` | one row per stock movement | 30K rows; `transaction_type` usage/purchase/waste/adjustment |
| `promotion_redemptions` | one row per redeemed promo | derived from orders with a promotion applied |

**Customizations on a panino:** taglia (Junior/Classico/Maxi), pane, tostatura, salsa.

**Genie semantics** (`src/03_create_genie_space.py` instructions): "fatturato"/"vendite"
= `SUM(orders.order_total)`; "scontrino medio" = `AVG(orders.order_total)`; best-selling
panino = count of `order_items` joined to `products`; low stock = `inventory_transactions`
aggregated per ingredient/store vs `ingredients.reorder_threshold`.

## 4. The Knowledge Assistant documents (6 PDFs)

Generated by `src/02_generate_ka_documents.py` and uploaded to the
`ka_documents` Volume. The KA does RAG over them.

| PDF | Covers |
|---|---|
| `manuale_operatore.pdf` | Operator manual: opening/closing, counter service, training |
| `ricettario_panini.pdf` | Recipes for the panini (preparazione, farciture) |
| `sicurezza_alimentare_haccp.pdf` | Food safety (HACCP), allergens, cold chain, sanitation |
| `guida_franchising.pdf` | Franchising: affiliation, store opening, royalties |
| `manutenzione_attrezzature.pdf` | Equipment maintenance (piastra, affettatrice, forno, frigo) |
| `accordi_fornitori.pdf` | Supplier agreements, lead times, reorder terms |

> FPDF uses latin-1 core fonts, so document bodies stay ASCII (straight quotes,
> "EUR" not the euro symbol, `-` bullets). Do not introduce Unicode punctuation.

## 5. Demo questions (Italian)

These exercise each routing path and a composite question:

- **Genie (structured):** "Qual è il panino più venduto questo mese?"
- **KA (procedural):** "Come si prepara il panino 'Nduja & Friarielli?"
- **Genie (inventory):** "Quali punti vendita stanno per finire la mozzarella?"
- **Genie (promotions):** "Quali promozioni sono attive adesso?"
- **KA (suppliers):** "Quanto tempo serve per riordinare il tartufo dal fornitore?"
- **Composite (both):** "Quali store sono a corto di mozzarella e qual è il lead
  time di riordino?" → supervisor calls Genie *and* the KA, then merges.

The app surfaces which subagent answered ("Calling agent… Analista Vendite / Ops
Bot") and renders KA source citations as links to the PDFs in the Volume.
